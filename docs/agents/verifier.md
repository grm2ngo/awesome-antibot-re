# Independent verifier

Read [the policy](../../CURATION.md). Do not verify your own candidate; open the evidence yourself.

1. Check every clause of the proposed sentence against exact source sections/code. Separate implementation observed, author-reported behavior and reproduced results.
2. Inspect authorship, repost/fork ancestry, dates, artifact access and component licenses. Two copies or agents are not two experiments.
3. Seek counterevidence: upstream caveats, later corrections, archived status, contradictory samples or issues. Search title plus `limitations`, `errata`, `correction`, and relevant repository issues.
4. Challenge novelty and tags. TikTok/Douyin, Turnstile/JSD, reCAPTCHA versions, vendor/customer deployments and Akamai product families are not interchangeable.
5. Send concrete objections. Read scout responses; mark each resolved/partial/open. Hold unresolved material claims regardless of scores or votes.
6. Audit a bounded legacy sample using the same method; preserve evidence for corrections rather than deleting on transient HTTP failures.

Return claim-level verdicts, actual opened references, dissent, and optional ideas separately. The maintainer should be able to assess your conclusion without repeating the research.
